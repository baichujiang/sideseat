scope. Only `test_001` and its six new QA profiles were enrolled. Both sides'
intentions carry that scope, so unrelated unscoped intentions cannot consume
the counterparts. This is existing course-scoped matching, not a changed rule or
a new security/authorization feature. Do not invite other users to this QA course.

are hidden and no course schedule or chat message was created.

`qa_mutual_` prefix. Names, bios and intention notes say QA/test and explicitly
describe synthetic profiles. No existing real user was edited. Passwords for
new peers were generated in memory; setup login sessions were revoked afterward.
No database migration, backend deployment or new TestFlight build was required.

resetting existing data. It is deliberately not an automatic recurring seeder.

Dry-run command (read-only):

```sh
node --env-file=.env --import tsx scripts/seed-together-demo.ts --production --run NEW_RUN --batch categories
```

Replace `NEW_RUN` with a fresh 1–12 character lowercase alphanumeric identifier.
Only after reviewing the dry run, provide the existing QA password in
`SIDESEAT_QA_PASSWORD` and add `--apply`. The production endpoint and database
host are explicitly checked. Never run the general `seed:test-accounts` script
against production for this task; it resets unrelated seeded profile fields.
