# Preview 118：发起后立即显示时间表

2026-10-18，Europe/Berlin。用户要求创建征集计划后就看到时间表，无需等待他人填写。
产品来源 `a2946b5fb0ed34e20eb2e75f4b45ff737c3b7fac`，已提交推送至
`codex/ios-uxui-20260922`。

## 行为

创建征集计划后，发起人直接看到完整时间表，0 人填写时也显示真实空表、人数和分享/复制入口。
「填写我的空闲时间」为表格上方独立整行按钮，填写可稍后进行。
保存自己的空闲后仍显示时间表；返回再打开也默认显示时间表。
朋友填写后在同一张表中更新人数，并增加选最终时间/邀请操作，分享始终保留。
创建动作改为「创建时间表」，首页下一步不再要求发起人先填写才能分享。

参加者保存后的等待说明、固定时间邀请、现有数据、API、确认版本和日历规则保持原样。
本轮只更新原生 Preview；后端和分享网页沿用 116 的发布。

## 验证

- 10 项 Swift 单元测试通过，覆盖发起人未填写也可分享、朋友先填写时可选时间，及现有角色/确认边界。
  [结果](./evidence/2026-10-18-plans118/unit-tests.json)。
- 真机创建专项 5 项通过：创建/取消、返回保留输入、两种时间方式、消息入口、中文深色最大辅助字号。
  这些用例在第一次运行中通过；之后仅调整详情里的填写入口。
  [独立专项结果](./evidence/2026-10-18-plans118/creation-tests.json)。
- 修复后的连续真机用例 **1 项通过、0 失败、0 跳过，113.682 秒**：
  首次创建 → 0 人空表/可分享 → 返回重开仍是空表 → 填写自己的空闲 →
  保存后 1 人时间表 → 系统分享/复制 → Safari 朋友填写 → 原生选时间/名单发邀请 →
  朋友明确确认 → 日历搜索/详情 → 返回同一计划。
  断言包括 0/1 人时间格、独立填写入口可用、自己的已选时段在分享栏上方。
  [结果](./evidence/2026-10-18-plans118/phone-flow.json)。
- Mac 实时核对 6 个正式 API 阶段：COLLECTING 的参与记录依次为 0、1、2，均无日历；
  INVITING 仍无日历；2/2 确认后唯一一条一小时日历，返回计划后仍为同一条。
  [API 边界](./evidence/2026-10-18-plans118/flow-api.json)。
- 三语言 strings 语法、Node 语法和 ESLint、真机签名构建及严格签名校验通过。

第一次连续用例已证明空表和重开正常，但标题旁的填写入口被手机系统悬浮按钮遮挡，未进入编辑。
改为独立整行按钮，并以姓名输入框实际出现作为进入编辑的断言；最终完整流程通过。
