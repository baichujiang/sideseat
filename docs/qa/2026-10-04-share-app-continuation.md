# 分享注册后的 App 引导

2026-10-04，Europe/Berlin。

## 修复

原先注册成功仅显示通知；App 入口需要 `opened` 且已建立 `connectionId`，等待回复或只添加日程时没有入口。

- 注册成功显示独立引导：确认账户创建、展示服务端规范化后的用户名、说明首次 App 登录方式、提供打开 SideSeat / 继续网页。
- 无聊天连接时进入 `sideseat://inbox`；已有连接进入对应 `sideseat://connections/{id}`；保存私人日程后进入 `sideseat://home`。
- 注册接受邀请仍先完成接受操作。注册添加日程仍先显示日程表单，保存或取消后均出现引导。
- 注册接口成功后即更新身份和页面步骤；后续刷新失败不会重新显示注册表单。未完成操作的错误仍显示。
- 关闭引导后，已登录访客仍有持久 App 入口；刷新后保留账户与消息。
- 中、英、德文均有引导。未打开 App 时提供外部浏览器/手动打开说明；若配置 `NEXT_PUBLIC_IOS_INSTALL_URL` 则显示安装链接。目前正式环境未配置该值，页面说明向分享者获取安装方式，未虚构商店地址。

## 生产验收发现并修正的时区问题

首次正式浏览器验收的注册、原生 API 登录、收到回复后定位聊天、刷新保留入口均成功，但两次页面加载各出现 React #418。原因是关闭状态的 dialog 仍渲染日程表单，`Intl.DateTimeFormat().resolvedOptions().timeZone` 在生产服务器 UTC 与浏览器本地时区之间不同。改为仅在 `modal === 'calendar'` 时渲染表单；没有使用 suppressHydrationWarning 掩盖差异。

服务器设置 UTC，新的引导用例浏览器设置 Asia/Shanghai，相关 8 项再次全通过，33.6 秒，无脚本异常；相关 ESLint / TypeScript 通过。早期超时轮次有一个 owner QA 账户因浏览器已关闭而未清理，已精确删除并确认该测试前缀剩余 0。测试清理增加对浏览器已关闭状态的处理，避免阻止数据库清理。
