# Preview 93 分享获客闭环验收

日期：2026-10-04，Europe/Berlin。范围：原生发布并分享意愿 → 游客看活动与空闲时间 → 匿名招呼 → 发布者在 App 回复并邀请 → 游客注册接受 → App 登录接续 → 双方日程与持续联系。

本轮使用 Preview 93 的冻结产品源码 `6ecd35884cb2f722196afa025c9e70d81a0d5b49`，只更新 UI 测试代码。原生界面运行于 iPhone 13 mini / iOS 26.5 模拟器，游客端是移动 Chromium。业务状态使用隔离 PostgreSQL 与真实本地 API，没有以 fixture 替代消息、计划、注册或日程写入。仅初始发布者账号由脚本创建。

## 结论：闭环尚未通过，已定位原生接续阻断

| 阶段 | 实测结果 |
| --- | --- |
| 原生发布、打开系统分享、复制公开链接 | 通过 |
| 公开活动与空闲时间、匿名招呼 | 通过；浏览分享页不创建账号 |
| 原生回复与计划邀请自动送达网页 | 通过；关闭 GET 轮询，写入到可见分别 596 ms / 1,196 ms |
| 注册并接受邀请、保留原游客身份和聊天 | 通过；用户总数 2，没有另建一个身份 |
| 日程写入 | 同一个已接受计划写入双方日程，共 2 条；发布者 App 中可见 |
| 网页链接打开原生 App → 登录 → 返回聊天 | **失败：强制校园资料／认证设置页挡住整个 App** |
| 新用户 App 日程、重新登录后原生持续联系 | 因上述阻断未到达，不计通过 |
| 发布者 App ↔ 已注册游客网页继续联系 | 补充验证通过；刷新后记录保留 |

最终采用的原生阶段为 3 项通过、1 项失败、0 跳过，其中一项通过是单独的网页接续补充场景。浏览器主流程在确认卡片选择器修正后，使用原会话接续到原生登录并发现真实阻断；补充网页场景单独通过。没有将调试接续描述为一次从头到尾全绿的复跑。[汇总证据](evidence/2026-10-04-share-acquisition/summary.json)、[最终数据](evidence/2026-10-04-share-acquisition/final-state.json)。

## 首要待修复 P1：快速注册用户无法进入 App 的既有聊天和日程

游客注册后仍保留真实的新用户状态：学校为空、语言为空、未认证，没有伪造校园身份。网页登录、接受邀请和两份日程写入均成功，原生 `/auth/login` 与 `/me` 也返回 200。但原生界面停在 `required-setup`，只提供 School、Languages used for matching、School verification 和 Log out；没有进入聊天或跳过设置的入口。[原生失败摘要](evidence/2026-10-04-share-acquisition/native-03-summary.json)、[实际界面辅助功能树](evidence/2026-10-04-share-acquisition/native-required-setup-ax.txt)。

原因：`AppRootView.canUseAppShell` 用 `readiness.ready` 控制整个 App；后端 `deriveNativeMVPReadiness` 要求校园信息、语言和 VERIFIED 状态全部完成。分享注册只升级账号并保留记录，与整个 App 的准入规则不兼容。因此此次不能判断“完成认证后深链接是否还会保留”，也不能声称原生接续成功。

建议后续为已注册用户提供受限的基础入口，允许访问本人已建立的聊天、已接受计划和本人日程；在使用校园发现／匹配等能力时再要求相应资料与认证。由后端明确返回能力，原生按能力展示入口，并保留登录前的待打开会话。不能通过把游客自动标记为已认证或全局删除准入条件来修补。需要一起验收身份隔离、既有关系访问、未认证用户边界、退出／换账号清理及延迟补资料后返回原会话，所以本轮记录为重大问题，没有直接改动。

## 已修复：未来意愿被数据库时区提前结束

原生第一次发布 12:45–13:15（柏林时间）的意愿时，12:13 刚发布就被标成 EXPIRED，导致分享入口消失。Prisma 的 DateTime 列以 UTC 无时区时间存储，原始 SQL 的 Date 参数却被绑定成 `timestamptz`，比较时 PostgreSQL 使用会话时区重新解释列值。柏林会提前结束，纽约会延后结束。

修复将参数明确转换为 UTC 无时区时间再比较；没有修改数据库时区、表结构或历史数据。回归覆盖 UTC、Europe/Berlin、America/New_York，ACTIVE / PAUSED、过去 / 未来及未定时间。修复前 3 项中 2 项失败；修复后连同现有意愿和分享回归共 **23 项通过，0 失败、0 跳过**。

修复提交：`5ec86688ecfe1b289d649e01b971a751efbb3279`，已推送当前工作分支。

## 待修复 P1：选中空闲时间没有结构化传给计划草稿

复现：分享页选择 13:15–13:45，游客发送自定义招呼，发布者回复后点击聊天里的意愿 → 提议计划。活动标题被保留，但草稿变成系统默认的 13:34–14:34，并要求重新确认时间。[原生截图](evidence/2026-10-04-share-acquisition/timing-handoff-gap.png)。

当前网页会把选中时间写入默认招呼文案；用户改写文案后，SEND 只发送正文。服务端建立会话时，`startsAt/endsAt` 固定为 null、`timeContext` 为 UNDECIDED。原始空闲时间仍保留在意愿快照中，但没有成为计划草稿的建议时间。

这是跨分享页面、接口和原生计划草稿的衔接问题，优先级 P1；本轮按“大问题先记录”保留，没有临时猜测用户选中的时间。主流程测试会明确确认计划页显示的时间后继续；后续日程一致性只证明双方保存同一个已确认计划，不表示该计划时间自动匹配最初的空闲时间。

建议后续传递所选窗口的结构化引用与意愿版本，在服务端校验仍有效；原生以该窗口预填建议时间并让发布者确认。用户改写招呼不能清除选择；多窗口、跨时区、窗口过期及意愿编辑均需定义回退规则。

## 测试边界与可复跑入口

- 系统分享面板通过“拷贝”取得真实链接，XCTest 在测试内记录剪贴板 URL。iOS 的“允许粘贴”由代理通过模拟器 UI 完成，未要求用户操作。
- 游客页面收到回复与邀请时关闭普通 GET 轮询，检查 SSE 自动更新。延迟以数据库写入到浏览器可见计，本地结果不能当作生产网络 SLA。
- 原生首次回复会从招呼页切换到聊天页，收起键盘是正常行为；测试不能套用连续聊天的“发送后键盘保持”断言。
- 聊天容器出现不等于其异步意愿上下文已经加载；测试需等待实际入口出现再点击。
- 早期分享按钮查询类型、测试结束后的剪贴板读取、首次回复键盘判断以及上下文等待失败均保留在临时运行目录，没有记为通过。修正测试后从干净访客状态复跑；失败访客清理记录已保留，发布者的原生发布记录没有伪造。
- 此轮不覆盖小红书 SDK 真正发布、第三方 App 内置浏览器、未安装 App 的下载后恢复对话、真机浏览器到 Preview 的系统分发或 VoiceOver。App 接续测试使用网页提供的同一个 URL，由 XCTest 交给 iOS 打开。
- 当前注册仍需设置密码；进入 App 后仍需登录。它不是免密一键注册或自动登录，本轮不改变这个产品方案。
