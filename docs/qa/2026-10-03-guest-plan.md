# 游客消息与计划邀请（2026-10-03）

## 修复

原分享页每 4 秒发起一次完整消息请求，计划消息只显示“在 SideSeat 查看”。现在使用同源、Cookie 鉴权的 SSE 持续同步：服务端每秒串行读取一次当前对话，变化时直接下发完整快照。切回页面、重新联网会同步；连接中断时临时使用 2 秒轮询。后台页面关闭连接；流定期重连重新验证会话。没有新增消息基础设施或数据库迁移。

邀请卡片展示活动、日期时间、时区、地点、备注和最新状态。游客点击“注册并接受邀请”后，内联表单保留邀请上下文，提供可修改的默认用户名和密码输入。注册升级同一个 User；随后重新检查邀请状态，调用现有 `/api/v1/plans/{id}/accept`，创建双方的计划日程。页面提供进入原生聊天的链接，提示使用相同账号登录。没有跨浏览器/原生的自动登录令牌。

完整测试发现接受 Mutual 计划会自动结束来源意愿，旧分享权限因此让已建立的对话中断。本次保留持有效分享链接、属于该意愿既有 Mutual 对话的参与者访问；新访客不能通过结束的意愿建立联系。撤销链接、Block、审核限制仍中断访问。

## 本次验证

- 真实 PostgreSQL 分享集成测试通过。
- 两条移动 Chromium 端到端测试通过：原匿名联系→注册→个人提醒；新匿名联系→原生回复→邀请卡→注册并接受→双方日程→原生账号登录→取消同步→结束后继续发消息→Block。
- 新邀请测试禁用普通 GET 消息请求，验证回复与邀请确实经 SSE 到达；额外检查未登录不能读取流、游客不能跳过注册接受邀请、新访客不能读取已结束意愿。
- 主工作区与受控候选 TypeScript、修改文件 ESLint、diff whitespace 检查通过。生产构建通过。
- 实际生产域名 14 项流程检查通过；此次样本回复延迟 408 ms、邀请延迟 510 ms（从发送 API 返回到流收到更新），不是对所有网络状况的延迟保证。
- 生产临时 QA 用户及关联数据已删除；生产凭据临时文件已移除。Privacy、Support、API 配置、AASA、小红书回调页健康检查通过。
- 原生源代码未修改，无需重装 Preview。未声称完成手机人工 UI 验收；可用现有 Preview 与外部分享页面测试。
