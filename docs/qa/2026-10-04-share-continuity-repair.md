# 分享获客接续与时间预填修复验收

2026-10-04，Europe/Berlin。本次按用户批准修复上轮报告的两项 P1。

## 修复

- 后端分别返回基础 App 访问资格 `canUseApp` 与校园资格 `ready`。已注册且完成账号创建的用户可进入原聊天、计划和日历；未认证身份不变。校园资料设置放入同行入口，保留底部导航和“先去聊天”。登录前会话链接优先于可选新手引导；退出清除待打开路径，缓存按用户隔离。
- 分享页把时间段和意愿版本独立于问候语提交。服务端在锁定意愿后验证，幂等键覆盖正文和时间，快照保留选择。原生计划草稿预填原时间并要求确认；已过期建议要求重新提议。选择只是建议，不缩短既有对话权限，也不自动成为计划。
- 发送前意愿变更时保留正文、刷新可选时间；也可明确选择“时间可以一起商量”。已发送建议作为历史上下文保留，后续计划由发布者明确确认。旧消息不猜测补填时间。

## 实测结果

隔离 PostgreSQL 与本地真实 API，原生 iPhone 13 mini / iOS 26.5 模拟器及移动 Chromium；只预建发布者账号，发布、招呼、邀请、注册、接受与后续消息均走实际界面。

| 阶段 | 结果 |
| --- | --- |
| App 发布意愿、系统分享复制实际链接 | 通过 |
| 游客看时间、改写问候语并发送 | 通过 |
| App 回复并按所选时间提议计划 | 通过，开始与结束精确匹配 |
| SSE 自动显示回复与邀请 | 通过；GET 轮询关闭 |
| 注册原地升级并接受，双方日程写入 | 通过，同一 User ID、一个计划、两份日程 |
| 分享链接打开 App、登录后直接进入原聊天 | 通过；未跳过新手引导的产品逻辑 |
| 新用户原生日程、校园入口限制与返回聊天 | 通过 |
| 发布者原生日程及双向继续联系 | 通过 |
| 新用户重新登录、原记录仍在 | 通过 |
| 浏览器刷新保留聊天、结束意愿拒绝新访客 | 通过 |

本轮完整主流程 `resumedAfterRegistration=false`，五个原生阶段全部通过。另有 10 项后端测试、10 项原生模型测试、13 项 OpenAPI 测试和 1 项浏览器过期选择恢复测试通过；类型检查、定向 lint 和 OpenAPI 一致性检查通过。完整流程没有以预建计划、伪造校园认证或接续上轮失败结果代替测试。
