# SideSeat 存储清理、验证与 Vercel Pro 成本评估

初次审计：2026-09-30；发布更新：2026-10-01。代码范围：当前 `codex/ios-uxui-20260922` 工作区。下文保留初次本地验证和成本模型的原始范围；用户确认后，本版后端、新增数据库表和 18 条旧聊天图片迁移已发布生产。没有升级套餐。详见[本次发布记录](../releases/2026-10-01-storage-production.md)。

## 结论

Neon 保存结构化业务数据、Blob 保存文件的分工可以继续使用。本轮依次处理了聊天图片访问、文件回收、数据库图片正文兜底、上传滥用和聊天空闲查询开销。每一步先确认问题，修复后测试，再复查；最后一轮相关代码检查及回归未发现新的阻断缺陷。这里的通过范围是本地 PostgreSQL、隔离文件存储和真实 HTTP API，并不代表生产配置已修好或已经完成线上压测。

只读核实：Vercel 团队当前是 **Hobby / active**；SideSeat 开启 Fluid Compute，函数区域为 `iad1`。生产变量中有公开 Blob 与私有认证材料 Blob 的凭证名称，可让聊天复用现有私有存储；本轮没有读取或输出这些凭证值，也没有验证该存储的实际区域/访问模式。未看到 `CRON_MONITOR_URLS`、`DATABASE_BACKUP_PROVIDER`、`DATABASE_BACKUP_RETENTION_DAYS`、`DATABASE_RESTORE_TESTED_AT`。`vercel usage` 返回 404，不能将其解释为用量为零。

2026-10-01 发布补充：已实际验证公开/私有 Blob 读写及隔离，存储区域均为 `fra1`，函数仍为 `iad1`；18 条旧聊天图片迁移完成。本报告成本表仍为注明的区域与活动量情景估算，跨区域的实际传输费用需要用账单校准；发布验证不等于生产压测。

## 按顺序发现、修复、测试、复查

| 步骤 | 已确认的问题 | 修复与验证 | 复查结果 |
| --- | --- | --- | --- |
| 1. 聊天图片访问 | 新图片使用永久公开地址；原始地址直接出现在聊天响应 | 新上传进入私有 Blob；通过消息专属读取接口检查参与者、屏蔽、账号状态和撤回状态；响应签发 1 小时有效链接，兼容现有客户端 | 修复重试响应复用过期链接的问题；真实 API 验证双方可读、第三人不可读、签名篡改/到期拒绝、屏蔽和撤回后拒绝 |
| 2. 文件回收 | 删除账号只处理部分材料；删除失败被吞掉；上传后放弃的图片无回收 | 在删除业务记录的事务中写入持久化删除任务；失败保留并重试；扫描无引用文件，保留 24 小时宽限；账号删除包括级联删除会话内双方附件 | 补上换回系统头像的清理路径；验证事务回滚、失败重试、分页扫描、共享引用和过期但仍保留的历史内容；历史迁移脚本实际运行通过 |
| 3. 存储缺失行为 | 未配置 Blob 时把 base64 图片写进 Neon | 各上传入口统一文件签名/尺寸校验；缺配置返回 503；新帖子和聊天不再接收内联图片 | 已有内联图片仍可读取；旧帖编辑可以保留原有图片；49 项相关基础测试与实际上传/删除接口通过 |
| 4. 上传成本限制 | 聊天和旧 Web 上传缺少统一限制；聊天上传重试产生新文件 | 跨头像、生活照、帖子、聊天共用每分钟 12 次、UTC 日窗口每天 50 次；新文件最大 2 MiB，最大 4096×4096；聊天按 Idempotency-Key 复用上传结果 | 原生客户端原已发送幂等键，补齐 Web；测试跨入口限额返回 429/Retry-After、重试复用地址、被屏蔽后不可上传；认证材料保留原有 5 次/小时和独立大小限制 |
| 5. 空闲聊天成本 | 每 500 ms 查询历史清理水位和消息事件；读取端取消缺少明确停止处理 | 无新消息时按 0.5→1→2 秒放缓；有消息恢复较快查询；读取端取消立即中止循环 | 测试先复现旧行为，再验证修复；9 项实时 API 回归覆盖重连、撤回、群聊/课程聊天、游标和未读 |

空闲稳定状态，每个聊天流的两项基础查询由约 240 次/分钟变为约 60 次/分钟，另有权限复核。此处是代码频率计算，不是生产数据库负载测量。活跃消息有额外查询，首次从空闲收到消息可能增加最多约 2 秒的轮询等待。

删除任务由现有 `student-verification-retention` Cron 一起处理，保持每日 03:45 UTC，兼容当前 Hobby。每轮每类存储最多扫描 500 个对象、处理 200 个删除任务，并保留扫描游标；这不是“所有文件 24 小时内必定删除”的承诺。升级 Pro 后可按积压量改为每小时执行。失败任务保留，重试时间采用有上限的退避，实际执行仍受 Cron 调度影响。

2. **外部告警**：为现有每个 Cron 配置独立的成功/失败/超时监控地址，填入 `CRON_MONITOR_URLS`。建议让文件回收失败和“连续两天未成功执行”可见。监控服务账号、接收人和通知渠道需要选择；本轮没有替用户注册服务或发送通知。

## Vercel Pro 能覆盖多少用户成本

这里的“覆盖”指 **Vercel 月账单保持在基础 $20 附近**，不是技术上最多只能容纳多少账号。注册人数不能直接用于计费容量判断。需要按日活用户（DAU）、请求次数、读图量和打开聊天的时长计算。

2026-09-30 核对的计费规则：Pro 基础费 $20/月，含一个部署席位和 $20 用量额度。Flat Rate CDN 启用后基础档为 100 万请求/月、1 TB/月；更高的 1000 万请求档额外 $20/月。它需要启用且满足适用范围，媒体分发占主要带宽的负载可能不适用；没有把它视为本账号已经启用。[Pro 官方规则](https://vercel.com/docs/plans/pro-plan)、[Flat Rate CDN](https://vercel.com/docs/pricing/flat-rate-cdn)。

`iad1` 模型采用 CPU $0.128/小时、内存 $0.0106/GB·小时，调用 $0.60/百万次。Blob 存储 $0.023/GB·月，写入/列表 $5/百万次，读取未命中 $0.40/百万次；Fast Origin Transfer $0.06/GB。长连接等待消息时内存仍计费，同实例并发共享能降低摊销，不能把每位用户都当成独占实例，也不能假设必定高效共享。[Fluid 计费](https://vercel.com/docs/functions/usage-and-pricing)、[区域价格](https://vercel.com/docs/pricing/regional-pricing/iad1)、[Blob 计费](https://vercel.com/docs/vercel-blob/usage-and-pricing)。

### 明确假设，非生产压测结果

30 天/月，全部团队额度供 SideSeat 使用，2 GB Fluid 实例，区域按 `iad1`；普通使用者每天 100 次 API 请求、30 张公开图片（300 KB/张）、2 次私聊图片读取（500 KB/张），平均 0.2 次上传、聊天页打开 10 分钟。API 假定 10 ms 活跃 CPU、150 ms 总时长；图片 CDN 命中 80%，私聊图片取保守未命中。每 DAU 平均保有 40 MB 文件，另预留 $3 基础存储/后台任务等预算。假设每个计费中的实例平均共享 1～5 个 SSE 请求，并展示敏感性。

这些 CPU、时长、共享率、平均文件存量均尚未从生产用量验证。每次网页构建、额外席位、其他项目消耗和长期媒体累积都会改变结果。模型没有把数据库轮询当成 CDN 请求；只计算对外请求和 Blob 获取。

| 日活用户 | Vercel 月账单情景范围 | 说明 |
| --- | --- | --- |
| 100 DAU | 约 $20 | 普通活动假设下在基础额度内 |
| 200 DAU | 约 $20～28 | 聊天实例共享差时开始超额 |
| 500 DAU | 约 $42～85 | 超过基础 CDN 请求档，且可能有函数超额 |
| 1,000 DAU | 约 $61～146 | 仍可扩容，已经不应按固定 $20 预算 |
| 2,000 DAU | 约 $98～268 | 必须用实际账单校准并发共享和活跃程度 |

表格假设 Flat Rate CDN 启用且业务符合范围，表示持续常态下对应档位的预算，不是突发当天立刻加收固定档位费；官方说明超出月容量后可能在下个周期调档。跨区域计费可能不同。上述数字不含税、Neon、AI、邮件或 Apple 费用。

可复算的基础 $20 容量：轻量使用（40 API/15 张公开图/3 分钟聊天）约 **440～590 DAU**；普通使用约 **140～250 DAU**；聊天很重（150 API/80 张公开图/30 分钟聊天）约 **47～135 DAU**。建议初期把“普通使用、约 200 DAU”作为预算观察点，不能承诺所有用户行为都只花 $20。超过它不等于系统承载不了，只是需要增加预算或进一步改善连接与媒体成本。

[计算脚本](evidence/2026-09-30-storage/cost-model.mjs)和[模型输出](evidence/2026-09-30-storage/cost-model.json)保存了全部参数。未启用/不符合 Flat Rate CDN 时，需按请求、Blob 传输和函数传输逐项重算，不能套用本表。

Neon 独立计费。当前结构下持续有人聊天会阻止数据库长时间休眠：例如 Launch 0.25 CU 连续运行 730 小时，计算费约 $19.35/月；0.5 CU 约 $38.69，1 CU 约 $77.38，另加存储、恢复历史等。这些是 CU 时长算术，不代表某 CU 已经通过对应 DAU 的性能测试。Vercel 的 $20 用量额度不能抵扣 Neon，也不能抵扣直接调用的通义 AI 和邮件费用。[Neon 计算价格](https://neon.com/blog/major-compute-price-reduction-on-neon)、[Neon 按量计费](https://neon.com/blog/new-usage-based-pricing)。
