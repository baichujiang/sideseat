# 聊天计划栏与反馈标签：补全修复方案

状态：设计方案，尚未实施、测试或发布。2026-10-04。
基线：Preview 91；应用源码 `b554b98810c2e935bcfa2751260907b82c4c0b1e`，交付记录 `b3288c01bf4e3a1ff67cc8760236896dba35064e`。
来源：[复测报告与两项未修问题](2026-10-04-plan-accessibility.md)。本方案取代聊天中先前不完整的方案；本次仅提交文档，手机仍为 Preview 91。

## 1. 目标与范围

修复两项已观察到的问题：德语最大辅助字号下聊天固定计划摘要溢出（P1）；已保存反馈标签截断（P2）。用户应能辨认正在查看的计划、阅读和输入消息、直接返回当前计划或最新消息、完整阅读并修改自己的反馈。

本阶段集中修改原生呈现和相应交互状态。沿用现有计划选择规则、聊天权限、反馈接口、计划和日历记录。普通字号空间充足时保留现有摘要。计划页与聊天共享的反馈组件一起修复；不改共享按钮的全局字号或尺寸策略。

完整状态、标题、时间仍在可滚动的原计划卡片中。顶部入口复用现有定位行为，不新增一套计划详情页。

## 2. 聊天顶部的呈现

普通字号且空间充足：显示现有完整摘要。
辅助字号或完整摘要无法满足下述空间预算：显示紧凑计划栏。短状态为主要文字，日历图标说明对象类型；不重复固定展示长标题和日期。

示意（文字和控件按可用宽度排布，不代表锁定高度）：

```text
[ 日历  已结束 › ]   [ 当前计划 ]   [ ⋯ ]
────────────────────────────────────
可滚动的消息、完整原计划卡片、反馈和续行操作
                      [ ↓ 最新 ]
────────────────────────────────────
消息输入区
```

- 点击状态入口：定位“当前正在查看”的原计划卡片，保留现有计划 ID／版本 ID；卡片较高时优先露出卡片顶部，不把整张卡片强行居中。
- 主要文字采用当前状态对应的短本地化文案：待我回复、等对方回复、已确认、进行中、已结束、已取消。具体状态归类复用现有领域逻辑；这次不重新定义拒绝、过期、旧版本等状态的业务含义。
- 中文、英文、德文均提供短文案。取消正文缩小和省略；允许必要的自然换行。完整读屏标签包含“查看计划”、原标题、状态、时间，保留原同伴信息。
- “当前计划”仅在用户查看的计划与当前默认计划不同且确有当前计划时显示；点击定位默认当前计划，不滚到消息底部。默认计划仍使用现有待回复／已确认等优先级，不改成简单按日期取最近。
- “⋯”仅在存在其他计划操作时显示，打开“查看其他计划”。沿用现有计划列表，不重复放入直接返回操作。
- 没有计划时不显示空计划栏；既有意愿来源入口保留。计划栏与意愿栏互斥，避免重复固定摘要。

## 3. 当前计划与最新消息：两个独立动作

“当前计划”与“最新消息”不能共用会根据数据变化悄悄改变去向的处理函数。

| 场景 | 顶部与返回行为 |
| --- | --- |
| 默认进入聊天，有当前计划 | 顶部反映默认当前计划；点击入口定位它；消息的初始定位沿用现有规则 |
| 从已结束计划进入，仍有当前计划 | 顶部反映选中的历史计划；直接显示“当前计划”；“最新”独立可用 |
| 从已结束计划进入，无当前计划 | 历史计划入口保留；不显示“当前计划”；“最新”独立可用 |
| 显式选中另一条当前计划 | 顶部与消息定位到选中的同一条计划；返回默认当前计划的入口按需要显示 |
| 没有计划／计划仍在加载 | 不展示空的可点击占位；加载完成不能夺走用户的阅读位置 |

“最新”沿用消息区现有的新消息入口，在离开底部时即显示，不以未读数量大于零为前提。收到新消息时合并显示数量，避免出现两个相同去向的按钮。短可见文案为“最新／Latest／Neueste”，完整读屏名称为“返回最新消息”并在有新消息时读出数量。

该入口位于消息区下缘，触区至少 44 × 44 pt；为它预留相应空间，不盖住续行按钮或输入框。到达底部后隐藏。点击才清除历史计划的显式定位状态并滚到底部；如有当前计划，顶部恢复默认摘要，但不得随之再次滚回计划卡片。

代码约束：现有 `ConversationPlanSelection.groups` 只包含当前计划。不能用这个列表替代历史计划定位来源；原消息中的计划快照和已选择的计划 ID 必须保留。如果目标消息加载失败，保留当前阅读位置并提供可重试提示，不跳到另一条计划冒充成功。

## 4. 宽度、键盘与高度分配

44 pt 是操作的最小触区，不是文字容器的固定高度。图标不挤压正文；长标题和完整时间放在消息卡片中。

布局顺序：扣除安全区域、导航栏和键盘 → 测量输入区及状态提示 → 为消息区保留可操作空间 → 判断完整摘要是否可用，不可用则采用紧凑栏。

- 紧凑栏先尝试横向；短状态与操作不能完整放下时，状态和操作分行。依据实际测量选择布局，不根据“德语”或某个型号写特例。
- 不允许内部文字要求完整高度、外层却被压缩而向导航栏或消息区绘制。高度不足通过改变布局解决。
- 最小受测竖屏（iPhone 13 mini）在最大字号、键盘展开时，消息区至少保留两行当前正文的高度，并能滚动。输入框至少容纳一行正文，发送和收起键盘可操作。
- 当前输入框最高增长到四行。仅在空间不足时按剩余高度降低可见行数，后续输入在文本框内滚动；保持全部文字、光标和组合输入。先验证既有输入区是否已满足预算，只有实测不足才局部接入高度限制。
- 键盘和字号变化以当前阅读消息作为锚点。处于底部时维持底部，正在阅读历史时保持历史消息附近；不因紧凑／完整布局切换而重建聊天或清空草稿。
- 同时检查已有意愿摘要、引用回复及错误提示对实际空间的占用。只修复本轮可复现的冲突；其他重大交互变化单独记录。

## 5. 草稿、阅读位置与明确跳转

| 用户动作／事件 | 必须保持或改变的状态 |
| --- | --- |
| 打开／关闭更多菜单或计划列表但未选择 | 计划选择、草稿、引用回复、阅读位置保持 |
| 点击顶部计划入口或选择一条计划 | 仅按用户选择定位对应卡片；可收起键盘，草稿和引用回复保持 |
| 点击当前计划 | 清除历史选择，定位点击时的当前计划；刷新后已不再有效则提示并留在原处 |
| 点击最新 | 清除历史定位，滚到底部并更新新消息提示；草稿不变 |
| 收到新消息、计划刷新、保存反馈 | 阅读历史时不强制跳底部，不擅自换计划；当前计划的状态可以就地更新 |
| 从再约／新意愿表单取消 | 回到来源页面及对应卡片附近；草稿与原记录保持 |
| 发布或接受新计划／发布新意愿成功 | 沿用既定成功去向，明确区分成功导航与取消返回 |

使用现有消息 ID、滚动锚点和输入状态。页面尺寸不变时，取消前后位置按已有约 12 pt 容差检查；尺寸或卡片高度变化时，检查同一阅读锚点仍可见，不机械要求像素完全一致。

## 6. 反馈的呈现与状态

空间充足的普通字号保留胶囊及编辑入口。辅助字号或完整文字无法横向放下时，使用全宽圆角状态块和独立的“修改反馈”入口。状态文本允许换行和自然增高；图标顶端对齐，不靠大图标挤占文字宽度。德语长词按正常本地化排版处理，不手工截词或用省略号替代。

布局选择必须先于 `showsSavedQuestion` 分支；该参数只决定是否显示问题，不应决定能否使用自适应布局。“发生／未发生”编辑选项也取消大字号下的一行限制和字体缩小。

| 状态 | 显示与交互 |
| --- | --- |
| 未回答 | 完整问题、发生／未发生两个选项；沉默不视为未发生 |
| 已保存 | 完整结果＋修改反馈；保留仅自己可见的语义 |
| 编辑中 | 展示完整选项及选中状态；增加局部“取消修改”，点击取消只收起编辑，不发送请求 |
| 保存中 | 明确显示保存进度，防止重复提交；不提前把新选择宣称为已保存 |
| 保存失败 | 保留最后一次已确认结果与编辑入口，错误可读，可重试；不清空原反馈 |
| 保存成功 | 依据服务端确认结果更新两个入口及续行文案，结束编辑；原聊天、日历和计划不因界面改动重复创建 |

继续沿用现有请求和刷新流程。实施时检查请求成功但读回失败是否会造成错误的“保存成功”呈现；若实测发现跨请求的状态缺陷，单独说明原因和所需范围，不把布局测试当作该问题已通过的证据。

反馈仍为参与者私有信息，不显示对方答案；发生反馈不等于再次同行许可。页面文案保持原规则：“发生”对应再约，“未发生”对应换个时间，发布新意愿保持独立入口。

## 7. 读屏与操作语义

- 焦点顺序：聊天导航 → 计划入口 → 当前计划／更多 → 消息内容与最新入口 → 输入和发送。
- 状态块读出完整反馈及私有属性；图标作装饰，不重复朗读。编辑入口明确读作“修改反馈”，选中项有选中状态。
- 菜单和表单关闭后焦点回到触发入口；显式选择计划后焦点到目标卡片，返回最新后焦点到最新消息区域。
- 保留自动化定位标识。静态状态不伪装成按钮；可交互项使用标准按钮语义。辅助功能标签验证与实际 VoiceOver 走查分别记录，不能互相替代。

## 9. 验收清单与发布门槛

| 验收组 | 必须覆盖 |
| --- | --- |
| 基本布局 | 中英德 × 普通／最大辅助字号；浅色深色代表场景；iPhone 13 mini及一个常规尺寸竖屏 |
| 计划上下文 | 原历史计划，有／无当前计划，多当前计划，长标题，取消状态；列表选择与点击入口指向同一 ID |
| 空间变化 | 键盘开关、长草稿、引用回复、字号变化；消息区可滚动，输入和发送可达，草稿／光标保留 |
| 导航与实时更新 | 回当前、回最新、新消息到达、重新加载、菜单和表单取消；不抢历史阅读位置 |
| 反馈 | 未回答、两种已保存结果、编辑取消、保存中、实际成功、一次受控失败；两个入口显示一致 |
| 可访问性 | 44 pt 最小触区、完整文字、读屏名称／值／顺序／焦点返回；至少一次真实 VoiceOver 走查 |
| 闭环回归 | `1→2→3→6→3` 的反馈后继续原聊天／再约；`1→2→3→6→1` 的再次发布、查看新推荐及原历史保留 |

视觉验收同时保存截图和控件边界证据；检查固定区域互不重叠、可见操作不被返回入口遮挡。自动化可点击不等于视觉合格；布局测量不等于读屏已验收。

区分两种证据：受影响路径的局部回归，以及从全新数据开始的完整闭环复跑。如果声称完整闭环通过，必须分别从独立新数据连续完成，不能复用旧报告冒充本轮结果。
