# 共同计划详情层级 · Preview 153

本轮范围为共同计划详情及其信息编辑、昵称、最终选时、邀请复核、参与者和分享页面。
活动未定时只在活动标题附近原位展开建议与单行输入，不新增模块或二级活动编辑页。
保留 App 联系人投递、手动提交、本机草稿、逐人确认、发起人正式发出及日历合同。

## 本地验证

- 原生 Preview 物理设备目标编译通过；独立真机 UI runner 编译通过。
- 42 项原生 TimePoll / PlanPresentation / PlanGuidance 单元测试通过。
- TypeScript、相关 ESLint、197 项路由清单与 13 项 OpenAPI 契约测试通过。
- 新接口 6 组真实本地检查通过：编辑后空闲与共享列表、发起人权限/字段边界、清空地点与邀请后冻结、明确接受与正式发布、未定主题保留建议、选定活动不被覆盖。
- 首轮接口断言混用了两种查看者的 `isMe`，修正为比较实际答复内容后全部通过；首轮证据保留。
- 本地检查使用隔离数据库和新建账号；每轮账号/计划清理并核对旧令牌 401 和公开链接 404。

### 真机检查中的修正

- 初轮 runner 等待 deep link 详情中本应隐藏的 TabBar，三个用例均在入口断言失败；改成等待详情标题。
- 第二轮活动添加通过，随后测试将中文「已选择」与英文比较而失败；修正本地化断言。
- 真机截图发现每条建议占用过多高度，收紧为活动名与感兴趣人数同排；最大字号改为纵排。
- 昵称卡片的父级辅助功能标识覆盖子项，增加明确的容器分组后，昵称编辑与草稿保留通过。
- 第三轮三项中两项通过；主流程在联系人列表停住，因为快速测试会注入固定联系人样例。
  完整流程改用临时账号在真机实际登录并从计划列表进入，避免将样例当作线上投递验收。
- 第四轮真实登录后，编辑、草稿、联系人投递、双方填写、邀请、接受和正式发布均通过，
  日历各一条；末尾取消确认因 iOS 26 小浮层隐藏取消角色的「保留计划」按钮而失败。
  将取消与删除确认改为同时显示两种选择的系统警告框，再用新账号完整复验。
- 所有失败或中断的 API 观察均保留；发生写入的轮次清理账号与计划后用新数据重跑。
  首轮未执行产品操作即在入口失败。最终结果另列，失败不计入通过。
