# 从图片添加日程

日期：2026-10-02。

## 实现与用户流程

日历 → 添加日程 → 智能填写 → 从图片添加 → 系统相册选一张图片 → 本机文字识别 → 核对／编辑文字（可点缩略图查看原图）→ 预览日程 → 编辑草稿 → 确认添加。

- 使用 Apple Vision 在设备上识别文字。仅访问用户选择的照片，不要求完整相册权限。
- 识别结果追加到原有输入，不覆盖已输入内容。选图和识别本身不调用后端；点击「预览日程」才将文字交给现有解析接口，确认添加才保存。
- 原图不上传、不写入服务端图片存储；用于对照的压缩预览仅保留在当前弹层内存。
- 选图入口与语音输入并列，识别中显示进度并禁用冲突操作。关闭页面取消识别结果回填。
- 图片最大 20 MiB，识别前按方向缩放到最长边 2,400 像素；空白／不可读取图片明确提示。文字上限与现有接口一致，为 2,000 个 UTF-16 单元；超长时保留文字，要求缩短后再预览。
- 中、英、德文文案已补齐。复用现有日程草稿编辑和批量保存接口，后端无变更。

## 验证

- 10 项 CalendarSmartAddStore 单元／集成测试通过。新增测试真实运行 Vision 识别含两个活动的图片，并验证手工前缀保留、只发送 text/locale、预览与保存分离、空白／损坏图片和超长文字限制。
- 模拟器真实 PhotosPicker 已手动选取生成的测试海报；成功识别两个标题、日期、起止时间。原图查看和返回均正常，随后进入草稿预览并确认保存返回日历。
- 注意：上述手动流程的「图片识别」是真实 Vision；后续解析与保存使用现有本地 dense fixture，固定生成六条草稿，不代表实际模型从该图片生成了六条。
- 原有文本预览／编辑／保存与语音启停的 2 项 UI 回归测试通过，0 失败；见证据中的 UI 测试摘要。
- Preview 65 签名构建通过；安装／启动结果见发布记录。

## 范围与待确认

- 本轮未调用生产 AI：本地未配置 DashScope API key，解析及保存以现有接口的 fixture／transport 测试验证。因此真实模型的识别后抽取质量仍需用户用实际海报验证。
- 此方案适合活动海报、文字式日程截图。密集多列课表可能丢失列与日期的对应关系；建议裁剪单个活动，并核对预览日期／时间。当前不承诺复杂课表完整导入。
- 入口归入现有带 Plus 标识的智能填写。本轮未新增收费或权限机制；现有自然语言解析接口尚未强制校验 Plus，不能把界面标识当作已完成的服务端付费限制。

## 成本估计

图片 OCR 在设备上执行，无新增云端 OCR／视觉模型调用，也无新增图片对象存储。仍发生原有文字日程解析的模型调用和普通 API／日程数据成本。
