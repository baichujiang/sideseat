# Preview 121：App 参与者直接在时间表填写空闲

2026-10-18，Europe/Berlin。用户要求 App 参与别人发起的计划时，也无需切换填写模式。
功能来源 `dbf6ed44ebf1150d596786624a0855d531287a96`，最终布局与测试来源 `9e668ca3aa88bfbafbc6d7a052d46066e758d05c`；
已推送至 `codex/ios-uxui-20260922`。

## 实际行为

征集阶段的发起人和参与者共用同一张可编辑人数时间表。参与者第一次打开、自动保存后、返回重开时都能直接点选或取消自己的空闲。
点按、长按拖选、当天选择、撤销、名字预填/编辑及没有空闲的既有答复保留。
勾选表示自己的选择，数字表示完整覆盖该半小时的总人数；旧半格保留部分状态。
当前草稿只替换自己的一份答复，其他人的答复不变；人数分母同时计入当前参与者，避免首次填写时颜色临时失真。
底栏持续显示真实保存状态和等待邀请，详细说明「填写空闲不代表确认参加」。

INVITING/CONFIRMED 等阶段继续使用原有明确确认与只读详情，另选时间时仍只读查表。
保留身份、已有记录、邀请版本、保存队列、失败重试、过期与 Calendar 规则，无 API/数据库/网页改动。
底栏铺满宽度，最大辅助字号使用一个纵向滚动页面，保留横向看日期；时间列加宽、日期栏增高，避免标签截断。

返回重开 → 取消自己的半小时，发起人记录保留 → 再次重开并恢复 → 当天选择/撤销 →
普通滑动不改数据 → 重开 → 深色最大字号检查 → 发起人 UI 登录并定最终时间/发送邀请 →
参与者 UI 登录并明确确认 → 日历搜索/详情 → 返回同一计划，仍为 2/2 确认。
最大字号检查复用同一真实参与者 token 和实际链接，以已有 QA 认证快捷入口启动；主流程均走真实 UI 登录。
