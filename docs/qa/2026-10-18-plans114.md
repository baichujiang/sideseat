# 计划页使用引导和界面更新验证

2026-10-18，Europe/Berlin。目标是让用户知道如何开始、当前需要自己做什么、下一步由谁完成。
实际发布与手机安装见 [Preview 114 交付记录](../releases/2026-10-18-preview114-plan-guidance.md)。

## 使用路径

| 阶段 | 用户现在能看到的引导 |
| --- | --- |
| 第一次进入 | 发起新计划、打开收到的链接，以及分享 → 约定 → 日历的简短说明 |
| 已有进行中计划 | 收起大幅介绍，按需要你处理、等待其他人分组；卡片给出具体下一步 |
| 创建 | 先选时间还没定或已经有时间，再填写对应字段；候选范围与实际活动时间明确区分 |
| 填写空闲 | 可见的分享/复制，30 分钟选时和保存提示；完成不等于确认参加 |
| 完成填写 | 发起人无其他答复时引导分享，有答复时固定显示选时间发邀请；参与人看到等待发起人的说明 |
| 确认 | 具体时间、名单、确认数、直接邀请剩余位置和日历规则；确认操作固定在底部 |
| 全员确认 | 已同步提示及去日历查看；取消放在计划菜单中 |

只读列表增加当前账号的 isOwner、didRespond 和 planningMode，避免对已填写的人重复提示填写，
或把直接邀请显示成 1/1 已确认。没有 Schema 或迁移变更，底层确认、保存和安全语义保留。

## 验证

- iPhone 14 Plus / iOS 26.5 隔离模拟器：**60 项通过，0 失败、0 跳过**。
  其中 50 项单元回归、3 项创建呈现与取消、7 项真实本地 API 界面流程。计划数据来自隔离 API；测试登录外壳及未测消息角标使用 DEBUG 夹具，不代表客户消息数据。
- 真实界面链路包含：首次创建 → 填写 → 保存完成 → 分享/复制 → 返回下一步卡片；
  发起人看表选择 → 邀请 → 参与人确认 → 两账号日历 → 原生 Calendar 导航；
  通知进入、保存撤销重开、取消清理日历、打开的邀请自然过期、中文深色只读。
- 真实 accessibility5 字号下的创建选择、字段滚动和底部操作通过；增加实际卡片高度断言，
  避免只设置参数却仍以普通字号运行。
- 本地 API 六项、OpenAPI 测试 13 项、191 个操作的契约校验、TypeScript、相关 ESLint 通过。
  中/英/德资源语法及 Git diff 检查通过。
- iPhone SE 第三代小屏模拟器补充通过同一完整创建、填写、分享和返回卡片流程，见[小屏结果](./evidence/2026-10-18-plans114/native-small.json)。
- 候选及正式 API 域名各五组线上流程通过：Chromium/WebKit 游客保存和重开、INVITED、逐人确认、两个账号日历/搜索及取消清理；到期征集只读/写入关闭；直接邀请跨过实际开始时间后关闭且无日历。新增列表角色和已填写字段在实际操作后核验。
- 默认 iPhone 14 Plus 已安装 Preview 114，严格签名及普通启动 PID 2151 核验；普通 SideSeat 97 保留。真机 runner 在 XCTest 连接前 exit 74（Xcode exit 65），实际交互用例执行 0 项；不能算本次真机 userflow 通过。runner 已卸载，Preview 已恢复普通启动。
- 两个线上测试账号已删除、剩余 QA 计划为 0，旧令牌 401、十个临时分享链接 404；候选临时访问已撤销。最终部署来源及回执见[交付记录](../releases/2026-10-18-preview114-plan-guidance.md)。

首次界面运行的四项失败按原结果保留：三个卡片定位失败源于新分组容器的无障碍标识传播，
增加 contains 分组后重跑通过；另一个旧用例期待已接受的人仍有确认按钮，已改为验证等待状态及到期关闭。
截图还发现创建弹层未继承大字号，已显式传入并复查。没有为测试恢复重复确认按钮。
