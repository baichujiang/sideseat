# 计划可靠性：Preview 113 验证

2026-10-18，Europe/Berlin。本批处理计划页审计中的通知漏失、保存回滚、过期收尾三项优先问题。
实际后端发布和手机安装以 [113 交付记录](../releases/2026-10-18-preview113-plan-reliability.md) 为准。

## 修复范围

- 通知使用真实接口的 `INVITED` 状态。升级时只重放 112 曾漏掉的共享邀请指纹，保留已读历史；过期邀请在开始时间移除，不必等待下一次网络刷新。
- 原生保存和编辑记录本地版本；旧 GET 的成功或失败都不能覆盖后续编辑、已确认保存或取消结果。保存继续串行合并，并保留失败重试及账号隔离。
- 邀请在开始时间、征集在最后候选窗口结束时派生为 `EXPIRED`。API、网页和原生统一只读；计划转入已结束，关闭填写和确认，不写日历。已确认事实及其日历不因这条规则改写；无需 Schema 或迁移。
- 当前可见的双人聊天计划同步关闭过期接受入口和待处理计数；兼容协调器没有重构。

## 完整流程与结果

| 层次 | 验证结果 |
| --- | --- |
| 本地浏览器与 API | 15 项通过：五人及四选五、游客/同名继续填写、昵称、自动保存/失败重试、完成/返回修改、全天时间表、过期征集/邀请及双人计划 |
| 既有双人 API | 创建、接受、拒绝、反提议及消息/日历集成，两项通过 |
| 领域与契约 | 9 项时间域测试、13 项 OpenAPI 测试；191 个实现操作与契约匹配 |
| 原生回归 | 独立 iPhone 14 Plus / iOS 26.5 模拟器累计 53 个不同用例通过：46 单元测试、3 创建呈现、4 真实本地 API 流程 |
| 静态与构建 | TypeScript、相关 ESLint、中/英/德资源语法、diff 检查及签名 Preview 构建通过 |

四个真实 API 原生流程：

1. 选时自动保存 → 当天全选 → 撤销 → 完成填写 → 返回列表 → 重开保留准确选择；完成仍是征集，不等于确认参加。
2. 真正 `INVITED` 通知 → 打开邀请 → 确认 → 两账号各一条日历 → 真实登录搜索日历 → 只读详情管理原计划 → 发起者取消 → 两账号日历清空。
3. 打开的邀请跨过实际开始时间 → 自动显示过期 → 确认入口消失 → 返回已结束 → API 为过期，日历为空。
4. 中文深色过期征集只读，隐藏昵称编辑、选时与邀请操作，显示重新安排引导。截图检查发现返回按钮对比度不足，调整样式后定向复查。

初次真实 API UI 运行有两项夹具失败：未加入的固定计划不会出现在个人列表；旧 Calendar DEBUG 搜索夹具不读取真实 API。
分别改为已加入但仍未全员确认的三人计划、真实账号 UI 登录后重跑通过。产品行为没有为夹具改造。
真机结果单独记录，不能把模拟器和安装成功写成真机交互验收。
