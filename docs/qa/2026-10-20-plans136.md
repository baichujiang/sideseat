# Preview 136 — coalesced availability autosave

App and shared-browser timetable edits remain immediate and save automatically.
After 700 ms without another committed edit, send only the newest complete selection.
Keep one write in flight per viewer; edits during that write retain their own quiet
period. Leaving the detail, backgrounding or retrying flushes the pending snapshot.
Only an acknowledged final snapshot is labelled saved; a failed write preserves
newer local choices and stops until retry or another edit. Native account generation
is captured when the draft is made, including the debounce interval.

The public response route reuses the save service's authenticated response instead
of fetching the same full plan and guest session again. Identical persisted
responses skip the response, guest and plan writes under the existing transaction
and validation. No schema, dependency, API contract or invitation rule changes.
