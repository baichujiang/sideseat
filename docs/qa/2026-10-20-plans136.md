# Preview 136 — coalesced availability autosave

App and shared-browser timetable edits remain immediate and save automatically.
After 700 ms without another committed edit, send only the newest complete selection.
Keep one write in flight per viewer; edits during that write retain their own quiet
period. Leaving the detail, backgrounding or retrying flushes the pending snapshot.
Only an acknowledged final snapshot is labelled saved; a failed write preserves
newer local choices and stops until retry or another edit. Native account generation
is captured when the draft is made, including the debounce interval.

The public response route reuses the save service's authenticated response instead
of fetching the same full plan and guest session again. Identical persisted
responses skip the response, guest and plan writes under the existing transaction
and validation. No schema, dependency, API contract or invitation rule changes.

  checks**, across Chromium and WebKit. Ten rapid ordinary clicks retain all 20
  quarter-hour IDs and produce **one save** in each engine. Slow replies do not

  **300.021 seconds**, with **12 API boundaries**. Includes edit/undo/reopen,
  roster drafts, cancelled rescheduling, explicit acceptance, unique Calendar and
  returning to the same plan. This journey began on the previous backend and
  finished across promotion; all native code is the final 136 source.
- After promotion, physical **first visit → create → share/copy → Safari guest
  availability → App invitation → Safari explicit acceptance → App Calendar/search
  → same plan** passes in **168.116 seconds**, with **8 API boundaries**, entirely
  on the final backend/share page. Guest edits preserve the organizer; Calendar
  remains empty before confirmation and contains one one-hour entry afterwards.
  Actual native/Safari save screenshots were inspected.
- Seven valid public health routes return HTTP 200. The scoped 1h error/fatal query
  returned no path groups in retained logs. api.sideseat.de and www.sideseat.de
  resolve to the promoted candidate, with no rebuild. The reused full-flow QA
  script has one existing prefer-const lint warning and no lint errors.
