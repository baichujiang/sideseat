# Preview 135 — invite without an availability prerequisite

Owner correction, 2026-10-19: someone who has not filled availability must still be
able to receive a formal invitation and explicitly confirm the proposed time.
The former organizer-only/other-response UI gate and response-only roster API made
this path impossible. Removing only the hidden button would not fix it.

## Implementation and contract

- Choose final time is always present for a collecting-plan organizer, even at zero
  responses. The timetable still distinguishes final-time drafts from availability.
- With no other respondents, review directly offers a total count, including the
  organizer (default two), and Create invitation link. No preliminary mode choice,
  fake participant or duplicate plan is created. Returning to adjust the time keeps
  this count and other review drafts. Cancelling the review commits nothing.
- Existing response-based invitation selection remains the default when friends
  have responded. Invite more friends by link is a secondary option to add new
  people. Known selected respondents retain individual pending invitations.
- Optional linkParticipantCount on the existing send endpoint explicitly opts into
  the existing FIXED link-joining rules. The same root/token, slots, responses and
  activity data remain. Old requests retain their closed-roster contract.
- The organizer accepts on creation of the formal invitation. Other App accounts
  and browser guests see the final-time highlight and explicitly accept/decline,
  with no availability response required. Calendar waits for the displayed total
  and all selected people. Existing FIXED capacity/version/cancellation rules apply.
- No schema, migration, permission or dependency change. The share UI already
  supports fixed invitations and is reused without a new web visual redesign.
