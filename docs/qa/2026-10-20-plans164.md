# Preview 164：共同计划紧凑详情

## 交付范围

按确认的排版落地原生 App。删除参与昵称卡片、编辑昵称弹窗及两个无调用视图；保留已存姓名和网页填写人规则。活动/状态同排，发起人/地点/编辑同排，日期/时区独立一行。普通时间表上方只显示已提交人数和至多三个姓名首字头像，超出显示 +N；整行可点，打开原有完整人员/进度页。未提交的 App 联系人继续在完整名单中显示原状态，不计入填写人数或头像。

去掉「大家的时间表」、填写说明和图例；撤销在时间表左上角，空闲提交和最终选时在底栏并排，大字号纵排。未修改 TimePollStore、API、Schema、邀请、接受、发布、到期或 Calendar 规则。原有草稿、半格、拖选、全天选择、撤销、手动提交和等待/接受/拒绝继续沿用。

## 实际验证

- 38 项 Navigation/PlanPresentation 单元测试通过。
- 模拟器使用真实双账号，从创建、保留未提交选择、发联系人卡片、双方提交、打开名单、选最终时间、核对邀请、明确接受、发起人正式发出到日历搜索，完整流程 **188.293 秒**通过。八个独立 API 阶段核对人数、精确空闲 ID、唯一消息卡片、邀请版本与日历记录通过。
- 默认 iPhone 14 Plus 同一真实链路 **181.087 秒**通过，八阶段 API 通过。分享时答复仍为零；只在手动提交后计入人数；填写和投递均不代替接受；发布前日历为零，发布后双方各一条。
- 独立展示计划由八名游客真实提交答复，用于验证三头像/+5、完整名单、0 人空表和深色最大字号。初轮标准字号 **24.784 秒**通过；最大字号用例误点被固定底栏遮住的离屏人数行，截图保留。测试改为先滚动并验证人数行位于导航栏/底栏之间，再点开；最终标准 **24.381 秒**、深色最大字号 **37.624 秒**通过。
- 最终包「时间已定＋朋友提议活动」真实双账号创建、投递、提议、选择活动、正式邀请、接受、正式发出和日历完整链路 **151.484 秒**通过，七阶段 API 通过；固定起止保持不变，发布前无日历，发布后双方各唯一一条且起止完全一致。

呈现计划的数据准备与真实主流程明确区分：两个主流程的产品操作全部由 App 完成，Mac 只准备一次性账号/联系人并读取 API；八名游客的额外答复仅用于多人呈现检查。没有把固定样例作为完整业务验收。
