# SideSeat — Capacitor iOS shell

SideSeat is a **Next.js** app (server components, API routes, cookies). The iOS app is a **native WebView wrapper** that loads your deployed site (or local dev server), not a static export bundled inside the IPA.

## Prerequisites

- macOS with **Xcode** (and iOS Simulator or a device)
- Node.js (same as the web app)
- Apple Developer account (for TestFlight / App Store later)

## Branch

Work happens on `feat/capacitor-ios`.

## Quick start (simulator + local dev)

1. Start the web app:

   ```bash
   npm run dev
   ```

2. Point Capacitor at it and sync the native project:

   ```bash
   npm run ios:dev
   ```

   This sets `CAPACITOR_SERVER_URL=http://localhost:3000`, runs `cap sync ios`, and opens Xcode.

3. In Xcode: pick a simulator → **Run** (▶).

The simulator can reach `localhost:3000` on your Mac.

## Physical iPhone (same Wi‑Fi)

1. Find your Mac’s LAN IP (e.g. `192.168.1.42`).

2. Run Next bound to all interfaces:

   ```bash
   npm run dev -- -H 0.0.0.0
   ```

3. Sync with that URL:

   ```bash
   CAPACITOR_SERVER_URL=http://192.168.1.42:3000 npm run cap:sync
   npm run cap:open:ios
   ```

4. On the device, use the Xcode run target for your phone.

## Production / staging

Set the URL to your deployed host before sync:

```bash
CAPACITOR_SERVER_URL=https://your-app.example.com npm run cap:sync
npm run cap:open:ios
```

Archive in Xcode (**Product → Archive**) for TestFlight or the App Store.

Ensure `NEXT_PUBLIC_APP_URL` (and cookie/session settings) match that host so login and API calls work inside the WebView.

## npm scripts

| Script | Purpose |
|--------|---------|
| `npm run cap:sync` | Copy web assets + config into `ios/` |
| `npm run cap:open:ios` | Open `ios/App` in Xcode |
| `npm run cap:run:ios` | Build and run on a connected device/simulator (CLI) |
| `npm run ios:dev` | Sync with `http://localhost:3000` and open Xcode |

## Environment

Add to `.env` (optional, for local convenience):

```bash
CAPACITOR_SERVER_URL=http://localhost:3000
```

`capacitor.config.ts` reads this when you run `cap sync` / `cap run`.

## What is committed

- `capacitor.config.ts`, `ios-shell/www/` (fallback placeholder)
- `ios/` — Xcode project generated by Capacitor

`ios/App/Pods/` and build outputs are gitignored.

Before TestFlight / App Store, use **[CAPACITOR_IOS_RELEASE_CHECKLIST.md](./CAPACITOR_IOS_RELEASE_CHECKLIST.md)** (Chinese, checkbox format).

## One product, three entry points

Web, PWA (Add to Home Screen), and the App Store shell all use the **same** Next.js host and database when the user signs in with the **same account**. See **[CLIENT_CHANNELS.md](./CLIENT_CHANNELS.md)** (Chinese).

Production: `NEXT_PUBLIC_APP_URL` and `CAPACITOR_SERVER_URL` must be the **same** `https://` origin before `cap sync`.

## In-app adaptations (web code)

The following run when `Capacitor.isNativePlatform()` is true (see `CapacitorBootstrap`, `useCapacitorNative`):

- Safe areas via `--safe-top` / `--safe-bottom` (`app-shell`, auth layout)
- Status bar does not overlay the WebView; splash auto-hides
- PWA “Add to Home Screen” / service-worker update bars are hidden (you already have the native app)
- Me tab: no install row; notifications card points to **iOS Settings** (not Web Push)
- Week “visible days” bar uses pointer drag (no iOS range loupe)

After changing `capacitor.config.ts` plugins, run `npm run cap:sync`.

## Limitations / notes

- **Push**: Web Push is for browser/PWA only. The native app shows a Settings guide; server-side APNs would need `@capacitor/push-notifications` later.
- **Stripe / OAuth** redirects must use URLs allowed in your app and Apple associated domains if you use universal links.
- Re-run `npm run cap:sync` after changing `capacitor.config.ts` or adding Capacitor plugins.

## Regenerate iOS project

If `ios/` is missing or corrupted:

```bash
npx cap add ios
CAPACITOR_SERVER_URL=http://localhost:3000 npm run cap:sync
```
